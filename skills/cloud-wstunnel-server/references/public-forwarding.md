# VPS 公网服务转发

用户已指定后续部署默认同时提供公网和 Tailscale 内网入口。复用已有中转，为各服务分配独立公网端口；用户明确要求仅内网时不开放公网。公网配置属于本次部署范围，不要求用户再次重复同一授权。

## 开启前确认

- 检查实际服务和公网端口，保留已有映射。反向 wstunnel 仍仅监听 VPS Tailscale IPv4，不为公网接入放宽为0.0.0.0，不改变云端平台代理或策略。
- 确认真正的登录访问控制：任何访客都能获取的会话/CSRF令牌不是登录门禁。已有登录有效时沿用；没有门禁则在部署前端增加独立认证，凭证只存私密配置，不复用服务器密码、API密钥或隧道凭证。交付明确的私密录入/获取位置。
- 精确批准内网及公网 Host，验证同源 Origin 和原会话令牌。需要兼容只接受本机地址的应用时，受限前端先验证外部地址、Origin和认证再转换上游请求；不能无条件改写任意Origin或关闭CSRF。保留源码/业务逻辑，优先部署配置；确需源码变更时按实际范围处理。
- 优先使用已有匹配域名和有效证书的 HTTPS 前端。IP地址的HTTP入口按用户选择配置并说明未加密；不声称 WSS 中转 TLS 同时加密用户到公网入口这段连接。不得占用已有WSS 443或其他服务端口。没有域名不阻止完成用户明确要求的IP入口。

## 选择转发方式

已有 Nginx/Caddy 等前端时，为本服务增加独立监听/路由，先验证配置再 reload，保留原服务。HTTP Host、重定向和资源地址必须与外部入口一致，认证按应用实际机制保留。

没有 HTTP 前端、应用已经有正确的认证和 Host/Origin 兼容配置时，可采用精确的 Linux NAT 规则，将公网 TCP 端口送到现有 Tailscale 反向监听。此方法不需要另开客户端或扩大服务端隧道权限；不提供额外认证或 HTTPS。

先检查实际网卡地址、iptables/nftables 后端及现有规则；以下是 iptables 示例，变量全部来自本次核实，不猜测端口空闲：

```sh
iptables -t nat -C PREROUTING \
  -d "$PUBLIC_IP/32" -p tcp --dport "$PUBLIC_PORT" \
  -m comment --comment "$RULE_LABEL" \
  -j DNAT --to-destination "$TAILNET_IP:$REVERSE_PORT" 2>/dev/null ||
iptables -t nat -A PREROUTING \
  -d "$PUBLIC_IP/32" -p tcp --dport "$PUBLIC_PORT" \
  -m comment --comment "$RULE_LABEL" \
  -j DNAT --to-destination "$TAILNET_IP:$REVERSE_PORT"
```

目的地址必须为该VPS实际公网IPv4。转发到VPS本机地址仍经过 INPUT，核实现有过滤/云防火墙允许这一服务；只添加必要单端口规则，不清空规则表或开放端口段。无需为本机DNAT开启全局IP转发。此 PREROUTING 方式用于外部请求，不保证 VPS 自己请求公网IP会经过同一路径；必须从用户设备验证。

将**本服务的精确规则**封装为带 start/stop 的幂等脚本及 systemd oneshot 单元：`RemainAfterExit=yes`，随网络就绪启动并 enable。start 用 `-C` 防重复，stop 用 `-C`/`-D` 仅删除同一规则。写入前检查已有同名文件，备份配置；不能保存/覆盖整机防火墙表来持久化这一项。环境不使用systemd时采用它已支持的管理方式。

对于 NAT 入口，应用看到的 HTTP Host 仍是公网地址；公网兼容和认证必须先完成，不能把内网认证通过等同公网认证通过。需要HTTPS或HTTP级门禁时选择相应反向代理。

## 验证与交付

1. 开启前，在内网转发入口用批准的公网 Host 测试真实认证门禁；错误Host、跨源变更请求和错误/缺失凭证必须拒绝。
2. 增加精确公网规则后，从用户设备分别访问内网与公网入口。验证未登录拒绝或登录跳转、正确授权后的实际页面、资源与绝对跳转，不能仅检查端口打开。
3. 公网IP入口不应跳回 Tailscale、127.0.0.1或错误端口。必要时修复已确认的公开URL或受限前端配置，不放松保护。
4. 检查原服务仍可访问，新转发管理单元 active/enabled。只记录“已配置开机恢复”，整机重启未实际测试时不声称重启实测通过。
5. 交付可点击的公网/内网 URL、登录配置来源、Docker转发恢复方式、VPS规则/单元及撤销方式。凭证值不进入部署登记或公开仓库。

退役时先停止对应公网转发单元或精确删除本服务规则，再移除对应隧道授权，保留其他服务。VPS规则即使保存，云环境重建也仍需要恢复Docker客户端和应用。
